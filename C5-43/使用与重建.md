# #43 代码与固件

2026-10-21；只提供本地材料。目标NUCLEO-C542RC / STM32C542RCT6，GCC14.3.1+st.2，SDK 2.1.0。未上板、未串口下载、未Go，不能当成量产升级程序。

## 文件身份与地址

`固件构建记录.json`记录10套构建的ELF/BIN哈希、初始MSP、入口、长度、实际编译单元数。官方Boot/GPIO各2套，教学Boot/V1/V2各2套；教学固件共6组位于`固件/`。

|目录|Flash起点|BIN字节数|用途|
|---|---|---|---|
|boot_v1_debug|0x08000000|71376|首先通过SWD下载，建议HEX|
|boot_v1_release|0x08000000|34712|Release复验时使用|
|app_v1_debug / app_v2_debug|0x08020000|6984|慢闪 / 快闪，UART下载|
|app_v1_release / app_v2_release|0x08020000|3696|Release复验，UART下载|

本批所有App只占全局页16（Bank2局部页0，0x08020000～0x08021FFF）。Boot链接限定低128KB，App链接高128KB；软件布局没有阻止协议访问Boot或选项字节。禁止全片擦除、错地址写入、修改OB或读写保护。App扩展后须按新旧镜像实际范围重新计算擦除页。

## 从官方ZIP恢复工程

在本文件目录打开PowerShell；输出必须是尚不存在的新目录，不覆盖已有工程。准备脚本验证ZIP及5个改写文件的SHA-256，再解压官方子集并覆盖这5个文件。ST版权与许可证随文件保留，独立归档在`许可证/`。

```powershell
python ./准备工程.py --sdk-zip '<SDK 下载目录>/STM32C5-MCU-HAL2.1.0_12-08-2026_06-37-21.zip' --out D:/C5_43_work
./构建工程.ps1 -ProjectRoot D:/C5_43_work -Role boot -Config Debug
./构建工程.ps1 -ProjectRoot D:/C5_43_work -Role app -Config Debug -Version 1
./构建工程.ps1 -ProjectRoot D:/C5_43_work -Role app -Config Debug -Version 2
```

Release将`-Config Debug`换为`-Config Release`。工具路径可通过`-ToolsRoot`指定已有bundles目录；脚本不安装工具。结果分版本保存到工程的`out43/`，避免重建V2覆盖V1交付文件。脚本只构建，不接板、不擦写。

本次准备脚本输出6738个文件，与实际编译的sdk_mod子集逐字节相同。已归档实际编译单元：Boot144个，App19个；没有新增C单元。`改写文件/`按SDK相对路径保存5个文件及对应diff。

## 上板顺序

以正文第06/07节、`上板验证清单.md`为准：先备份实验板旧内容，经SWD安装Boot并校验，B2复位后从UART以115200/8E1连接；只擦App页16，下载指定App BIN到0x08020000，校验通过后Go到0x08020000。再次CLI连接前先B2复位。V1慢闪、V2快闪，循环后B2/冷启动均回Boot等待，不自动启动App。

Boot保留检查在UART Go前分别回读低128KB。工具CLI帮助中的只读导出语法为`-u 0x08000000 131072 before_boot.bin`，另一次用`after_boot.bin`，每次新CLI前先复位再连。PowerShell用`Get-FileHash -Algorithm SHA256`比较。此操作本次未实板执行。

Go后的调试器应加载对应App ELF，并以附着方式观察`g_app_version`、`g_app_vtor`、`g_app_loops`。初始化MSP按向量首字核对，本批App为0x200007D0，不能强求它等于SRAM顶0x20010000。

教学跳转限定当前GCC/Cortex-M33配置，使用naked汇编，不能直接照搬到其他架构/编译器。没有增加签名校验、自动启动、断电恢复和回滚，也不验证其他接口。USBX和I2C/SPI仍是官方Boot初始化依赖；本篇仅接CN1，不占用USART做日志输出。
