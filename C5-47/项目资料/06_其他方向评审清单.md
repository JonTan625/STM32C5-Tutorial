# 项目三：另外两个方向的评审清单

读者可以不做记录仪，改做 CAN 节点或 USB 设备。交付要求与项目二相同：需求、资源表、状态/接口、测试表、可复现工程、已知限制。下面是评审时逐项看的内容，作者不提供这两个方向的参考实现。

## 方向 A：CAN 节点（基于 #40、#41）

|评审项|要看什么|常见问题|
|---|---|---|
|需求|报文 ID、周期、DLC、谁发谁收；总线关闭（Bus-Off）后怎么恢复|只写“能收发”，没写周期和错误恢复|
|物理层|收发器型号、两端终端电阻、CN18 接线；单板回环和双板实测分开写|拿内部回环的结果冒充总线实测|
|位时序|内核时钟、预分频、TSEG1/TSEG2、SJW，算出的位速率与采样点|只抄例程数字，说不出采样点|
|过滤|标准/扩展 ID、过滤器配置；不该收的报文确实收不到|只测了该收的|
|错误处理|错误计数读法；拔线、短路、对端掉电时的行为|没有构造过故障|
|勘误|ES0676 §2.12.1（边沿滤波下的失步）、§2.12.2（Tx FIFO 顺序颠倒）是否涉及你的配置|没查勘误|
|测试|正常收发、长时间计数、断线恢复、错误帧；对端用什么设备|只有一张“收到了”的截图|

## 方向 B：USB 设备（基于 #42）

|评审项|要看什么|常见问题|
|---|---|---|
|需求|设备类（HID/CDC 等）、报告格式或数据格式、主机端用什么验证|没写主机端验证方法|
|枚举|描述符字段、VID/PID 的来源与限制；复插、休眠唤醒后能否再枚举|只测了第一次插入|
|供电与接线|CN13 接口、板子供电方式；与 ST-LINK 供电的关系|供电来源写不清|
|时钟|USB 需要的时钟来源与精度依据|没核对时钟要求|
|勘误|ES0676 中 USB 相关条目（如 §2.13.1）是否涉及|没查勘误|
|测试|枚举、数据正确性、长时间运行、复插、主机休眠|只在一台电脑测过且没写系统版本|

## 三个方向共用的评审项

- 每条需求都有对应用例，每条用例都写了通过条件和需要的证据。
- 资源表区分“手册能力”和“本项目分配”，冲突写清楚。
- 构建记录有工具版本和产物哈希；实板结果写明谁测的、什么时候测的。
- 已知限制写清楚，不把没测的说成测过。
